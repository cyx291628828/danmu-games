# 弹幕五子棋 · 方案与实现说明

> 第七个游戏（`games/gomoku/`），2026-09-02 上线。本文记录玩法规则、界面布局、AI 算法与实现要点。

## 一、玩法（弹幕交互全流程）

### 1. 排队上座（等候队列）
- 观众弹幕发 **「排队」/「排黑」/「排白」**（兼容 `1`/`2`、`上座`/`报名`/`我要玩`）进入等候队列；
- 双人对决（pvp）下「排队」自动进人少的一队，也可明确排黑/排白；人机对决（pve）为单队列；
- 队列展示**头像 + 名字 + 排序值**；排序规则：**点赞 1:1 实时转化排序值**（`likePerPoint`，默认 1），
  **送礼每件额外 +`giftSortBonus` 分**（计件 = giftCount × repeatCount，受上限保护）；
- 排序值实时重排，同分先到先得；**队首标记「下一位上座」**。

### 2. 上座与落子权
- 当前局结束后，系统自动取各队列**排名第一**上座（pvp 双队列各取第一；pve 队首 vs 机器人）；
- **双人对决必须黑/白各一位观众到位才开局，缺任一侧只等待、永不补机器人**：只排了一侧时进入「等待上座」，
  展示屏浮层提示缺哪一侧（如「黑方已就位，等待白方发『排白』」），到齐自动开局；
  队列无人/人机模式无观众时同样等待，有人排队即自动开局；
- **只有上座观众的坐标弹幕才会被执行**：`H8` / `h 8` / `H行8列` / `8H` / `8列H行`
  （约定：**字母 = 行**（上→下，展示屏左侧标），**数字 = 列**（左→右，展示屏顶部标），字母与数字顺序不限）；
- 未上座者发坐标 → 服务端按状态给提示（排队中/未排队/未轮到），每人 8 秒一条防刷屏；
- 每手限时 `moveTimeSec`，超时按「中级」棋力**托管落子**防冷场；机器人有 `botThinkSec`「思考」演出延时。

### 3. 规则配置
- **连珠禁手可开关**（`forbidden`）：黑方 三三/四四/长连 禁手点落子被拒（盘面标红 ✕ 并提示原因），
  黑五连须恰好五子；白方无禁手，长连也算胜；关闭后自由规则（≥5 连即胜）——符合需求第 5 条；
- 棋盘 13/15/19 路可选（默认 15）。

### 4. 送礼悔棋
- 上座观众送礼 → 撤回**自己上一手及其之后所有落子**（对手已应手时 = 撤两手），轮次回给自己、落子限时重置；
- 次数上限 `undoMaxPerGame`（默认不限）、每次手数 `giftUndoPerGift` 可配；
- 排队观众送礼 → 加排序值；路人送礼 → 提示先排队（礼物不浪费）。

### 5. 计分与徽章
- **双人对决**：胜方 `pvpWinScore` 分 + 1 胜场，败方 `pvpLoseScore` 参与奖（平局双方各得参与奖）；
  均写入**全局共享排行榜**（`gomoku_wins` / `gomoku_score`）；
- **人机对决**：观众胜得 `pveWinScore` + 1 胜场，负得 `pveLoseScore`；机器人不计分；
- **徽章**：击败 Lv N 机器人 → 解锁「LvN」徽章（排行榜记录 `gomoku_badge`，只升不降），
  展示屏/控制台排行榜**名字后方显示金色徽章**；再次击败同级不再重复解锁。

## 二、界面（沿用现有主播台/9:16 竖屏规范）

### 展示屏 `/games/gomoku/public/stage.html`
**中栏三列布局**：左列 = 黑方落子者卡片（底部）+ 黑方队列（队头在下贴近黑方，队尾在上）；
右列 = 白方落子者卡片（顶部）+ 白方队列（队头在上贴近白方，队尾在下）——人机模式下右侧只显示机器人卡片；
棋盘居中，木纹 + 坐标（顶数字=列、左字母=行）+ 最后一手红点头像角标 + 禁手点 ✕ + 获胜连线金光 +
当前执子方卡片金框呼吸灯 + 回合倒计时条 + 结算横幅（胜者头像 + 得分 + 徽章解锁提示 + 下一局倒计时）+ 烟花。
下方：战报流 | 排行榜（含徽章）滚动吸收剩余空间；「等待上座」浮层提示缺哪一侧。

### 主播台 `/games/gomoku/public/control.html`
局面控制（开新一局/暂停/托管一手/主播悔棋/当前方判负/平局结束）+ 接入与模拟 + 实时状态（模式/禁手/双方座位卡）+
对局小盘 + **等候队列管理**（逐人移除/清空）+ 分组配置表单 + 战报日志 + 历史对局 + AI 播报面板。

## 三、AI 算法（10 级，经典 minimax 框架，参考主流开源五子棋 AI 路线）

> 调研结论：五子棋上「minimax + α-β 剪枝 + 棋型评估 + VCF/VCT 启发」是传统最强路线，
> 论文对比甚至优于朴素 MCTS；本项目用手动 α-β（零依赖、单进程 1s 时限内可控）。

| 等级 | 名称 | 行为 |
|---|---|---|
| 1 | 入门 | 随机落子（限邻域） |
| 2 | 新手 | 能成五先成五；其余大噪声贪心（不堵五） |
| 3 | 初级 | + 必堵对手成五；噪声 0.45 |
| 4 | 中级 | 噪声 0.12 的纯贪心（攻防速评） |
| 5-10 | 高级…棋圣 | α-β 迭代加深（深度 2/4/6/6/8/10） |

搜索级三件套：
1. **评估函数**：5 窗口棋型计数——窗口内含己方子数按 `[0,4,32,300,3200,260000]` 指数加权，
   对方窗口 ×1.06 鼓励防守；全盘逐线扫描 O(行数×长度)。
2. **着法排序**：单点攻防速评（进攻窗 + 0.9×封堵窗），候选限邻域 2 格、截断 Top 12-20。
3. **Zobrist 双 32 位哈希 + 置换表**（进程级共享，超 40 万条自动清空）：同时间预算搜更深，
   且把上一步迭代深度的排序作为下一步着法顺序（MVV-LVA）。
4. **VCF 杀棋检测**（6-10 级）：先于搜索判断「连续冲四」强制胜利——落子成四 → 对手被迫唯一堵点 →
   递归冲四；活四（两个成五点）/ 双四 / 堵点为禁手时直接判胜。深度 12、节点上限 2 万，耗时极小。

禁手联动：黑方搜索/杀棋/托管的候选点全部剔除禁手点；「黑方无合法落点」判定为白方获胜（困毙）。
单手最坏耗时（棋圣）实测 < 0.9s，不阻塞宿主 SSE/WS 推送。
